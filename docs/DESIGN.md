# 喵撲介面設計規格（液態玻璃 · 雙貓）

2026-11-10 起，四個平台（iOS 鍵盤、macOS 候選窗、Android 鍵盤、Windows 候選窗）共用這份規格。視覺方向來自 `assets/brand/cats/design_reference.png` 的 A–D 四稿；為了打字手感、鍵盤高度和效能，數值經過調整，以本文件為準。

## 1. 角色

兩隻貓要的是可愛，不是寫實；臉照設計稿和使用者自己的 3D 圖畫，五官都是平塗的簡單形狀，不加虹膜、反光這類細節。每隻用兩三個特徵讓人一眼認出：米米莫是黑毛配奶黃色的半瞇眼，莫莫是奶油色配可可色的耳朵和小爪，加上豆豆眼。

| | 米米莫（左） | 莫莫（右） |
| --- | --- | --- |
| 原型 | 黑色公貓。一整塊平滑的霧面黑，頭連著身體，兩隻尖耳，耳朵內側是稍淺的炭色；奶黃色的半杏仁眼，上眼皮是平的，往鼻子那側低，瞳孔是一道細直線（半瞇的「我都知道」表情）；小圓點鼻子，左臉三根粗白鬍鬚 | 重點色暹羅母貓。奶油色圓頭，可可色的耳朵（淺色外緣，耳窩較深）和小爪，臉中央一塊淺色；深藍綠的豆豆眼（純色橢圓），粗的 ω 嘴，右臉三根粗鬍鬚，沒有鼻子 |
| 素材 | `scripts/render_cats.py` 照設計稿量出輪廓，連同尾巴做成一個低而圓的高度場，打成霧面黑，額頭和背上有一層很淡的光澤；眼睛、鼻子、鬍鬚是平塗 | 同一支腳本用簡單形狀畫成，以同一個主光打成霧面，下巴和小爪下方有淡淡的陰影，腳趾線順著爪子的弧度；臉照 `momo_reference.png` 的樣子平塗，但不讀那張圖的像素 |
| 邊緣 | 輪廓內側一道細亮線，朝主光的一側較亮；深色鍵盤上靠它看得見輪廓 | 同左，略強 |
| 與玻璃的關係 | **在玻璃後面**：身體被玻璃左端蓋住並霧化，眼睛剛好露出玻璃上緣 | **在玻璃前面**：下巴擱在玻璃右上緣 |
| 表情格 | `open`、`happy`（^ ^）、`blink`（︶︶） | 同左 |

`assets/brand/cats/cats.json` 記錄錨點（皆為精靈圖寬高的比例）：

- `mimimo.aspect` 0.9135，`eyeBottomY` 0.538（眼睛下緣），眼睛中心 x 為 0.438／0.698（`eyeLeftX`、`eyeRightX`）。
- `momo.aspect` 1.0543，`eyeLineY` 0.50。
- `mimimo_tail.aspect` 4.02（尾巴，只用於膠囊造型）。

重新產生：`python3 scripts/render_cats.py`（輸出 iOS asset catalog、macOS `Resources/Cats`、Android `drawable-nodpi`、Windows `UI/Assets`，以及沒有即時背景模糊的平台用的 `*_frost` 霧化版本）。只想看母版時用 `--masters DIR`。寫檔前腳本會量母版上的錨點，偏離超過精靈圖的 0.004 就停下。

## 2. 玻璃造型

使用者可選三種造型；深色（D 稿）是外觀，不是造型，三種造型都有深色版本。

座標：玻璃矩形寬 `W`、高 `G`，原點在左上，y 向下。

- **膠囊（A，預設）**：圓角半徑 `G/2` 的體育場形。米米莫的尾巴從玻璃左端前方繞到底緣，粗細一致，尾尖是圓的，約在 `0.25 W` 處微微翹起，停在第一個候選的膠囊下方，不碰到膠囊。
- **波浪（B）**：上下兩緣平行起伏。波數 `n = max(2, round(W / 170))`，振幅 `a = 0.065 G`，中線內縮 `a` 使整體仍在 `[0, G]` 內。
  `u = (x − r) / (W − 2r)`，`r = G/2 − a`，`offset(u) = −a · sin(2π n u) · env(u)`，`env(u) = smoothstep(0, 0.12, u) · smoothstep(0, 0.12, 1 − u)`。
  上緣 `y = a + offset(u)`，下緣 `y = G − a + offset(u)`；兩端是半徑 `r` 的半圓。每緣取樣 64 點。內縮的描邊沿用外框的 `n` 和 `a`，不依內縮後的寬度重算。
- **雲朵（C）**：體育場底座 `y ∈ [0.16 G, G]`，與三個圓聯集：
  `(cx, r, 頂點 y) = (0.15 W, 0.58 G, 0)`、`(0.47 W, 0.75 G, 0.05 G)`、`(0.77 W, 0.56 G, 0.07 G)`；圓心 `y = 頂點 + r`。
  候選列置於底座的垂直中央。

「玻璃上緣 `T`」一律指膠囊／底座的上緣（波浪是上緣中線 `y = a`，雲朵是 `y = 0.16 G`），波峰與雲朵凸起可以高出它。貓對齊 `T`，展開鍵對齊候選列的垂直中央。

## 3. 玻璃材質

由下而上：

1. 投影：淺色 `rgba(60,40,70,0.12)` y=5 模糊 12；深色 `rgba(0,0,0,0.45)`。
2. 玻璃本體：iOS／macOS 用系統 Liquid Glass（`glassEffect`，淺色 `.regular`、深色 `.regular` 加暖煙色 tint）；Android／Windows 模擬：
   淺色填 `white 0.58`，深色填 `#3A302C 0.62`；玻璃覆蓋到的貓身改畫 `*_frost` 霧化圖並裁進玻璃形狀。
   Windows 例外：分層視窗拿不到背後的畫面，不能模糊。本體接近不透明（淺色 `#FAF9FC`→`#EFEDF4` 0.985，深色 `#483C37`→`#382E2A` 0.98），只留外緣 3 pt 透明邊（淺色 `white 0.42`，深色 `#3A302C 0.58`）；貓身的霧化在執行時模糊（sigma 3 pt），不用 `*_frost` 圖。
   Android 例外：鍵盤底是純色，玻璃後面只有貓，所以淺色本體填 `white 0.46`（柔和 0.60、通透 0.32），內部漸層上 `white 0.22` → 下 `0.04`；邊緣內側加一圈 9 pt 寬的柔光（`white 0.62`，深色 `#FFD6AA 0.10`）和內縮 4.2 pt 的細暗線表現厚度。玻璃裡的米米莫用 `*_frost` 圖以 0.59 不透明度畫（深色 1.0），圖在高度 0.84 處的那一列往下延伸到玻璃下緣，右緣 16% 淡出。系統對比設定為中或高時（Android 14 起）改為不透明。
3. 內部漸層：上 `white 0.32` → 下 `white 0.05`（深色上 `white 0.09` → 下 `0`）。
4. 虹彩焦散：沿下緣內縮 2 pt、寬 2.4 pt 的描邊，水平漸層 `#FFB8D2 #FFD9B0 #FFF4B8 #C9F2DD #BFD9FF #DCC8FF`，不透明度 0.75（深色 0.55），往上淡出；深色改暖銅 `#FFB27A #FFD4A0 #E8956A`。
5. 邊框：外緣 1.5 pt 漸層描邊，左上 `white 1.0` → 右下 `white 0.45`；深色為銅色 `#E7A877 0.9` → `0.18`。左上另有一段短高光弧。上緣內側一道 1.4 pt 亮線（`white 0.85`，深色 `0.22`，往下淡出）；淺色在下緣內側加一圈淡影（`#4D3857 0.07`）。3–5 是 iOS／macOS 實際出貨的數值。

開啟「降低透明度」或「增加對比」時，玻璃改為不透明：淺色 `#F4F2F6`、深色 `#2B2729`，保留邊框，去掉焦散與霧化。

## 4. 候選列

- **永遠單行**。候選寬度＝實測文字寬＋左右各 9 pt＋（日語）貓爪記號寬＋3 pt。展開面板的格子也把貓爪算進寬度。禁止換行；這正是之前日語候選被擠成直排的原因。
- 超過列寬 70% 的長候選（例如整句中日混合）中段省略（`…`），完整文字留給展開面板與無障礙標籤。
- 選中候選：玫瑰色膠囊，高 `0.70 G`，上 `#AB8689` 下 `#946D71`，白字中等字重，頂部 0.5 pt 白色內高光；深色 `#A88D8C`→`#8C716F`。其他色系由 `CandidatePalette` 衍生。淺色膠囊的白字對比在上端至少 3.2:1、下端至少 4:1（每個色系都是；空白鍵送出的就是這個詞，確認鍵和長按選取也用這個顏色），深色膠囊至少 3:1。
- 一般候選文字：淺色 `#3A3334`，深色 `#F5EFE9`。字級：手機 20 pt，桌面 15 pt。
- 候選之間 4 pt；按下時 0.95 縮放＋淡色膠囊。
- 日語候選：文字後接傾斜 −20° 的實心貓爪（字級的 0.45 倍），寬度計入量測。收合列最多保留一個日語候選。整頁都是日語候選時（日語模式）不加貓爪，收合列照一般候選排。
- 展開鍵：`chevron.down` 15 pt semibold，收在莫莫下巴下方，箭頭上緣的角離她的輪廓 2 pt（輪廓見 `CandidateRegionLayout.momoChinEdge`，`CatArtTests` 在圖上檢查三種造型都沒被蓋住）。
- 表情符號（iOS）：第一個候選是詞表裡的詞時（你好），它的表情符號排第二格（👋），和 Apple 鍵盤一樣；永遠不排第一，空白鍵和 Return 不會送出它，要點它才輸入。詞表是手寫的 `Resources/Lexicon/associations-hand.json` 加上 Unicode CLDR 的 zh／zh_Hant 表情註解（`DataSources/cldr-emoji`，`scripts/build-emoji-associations.py` 產生 `associations.json`）。macOS 不加這一格。
- 英文（iOS 的 ABC）：候選列放正在打的字的補完，拼錯時拼字檢查的第一個建議排在最前（`UITextChecker`，不需要完整取用）。只有點了才換掉那個字並補一個空白；空白鍵和 Return 照常輸入，不自動改字。
- 注音（iOS）：鍵上只有注音符號，所以打的鍵永遠不當英文字母讀（bpckbp 是 ㄖㄣㄏㄜㄖㄣ，不是英文字）。Mac 的鍵上印著字母，注音使用者會直接打英文字，所以仍會讀成英文。
- 展開面板（iOS）：格子裡的文字左右各 4 pt（日語候選再加貓爪和它前面的 3 pt）。手機最多 6 欄，窄螢幕減少欄數，讓單字格至少 44 pt 寬（`min(6, 寬 / 44)`）；全寬 iPad 鍵盤 `max(6, 寬 / 64)` 欄。面板右側只有刪除鍵，沒有自己的收合鍵；候選列的箭頭（此時朝上）關閉面板。
- 桌面（macOS、Windows）在候選前顯示小號編號（拼音 `1`…`7`，Windows 的頁面多一個中日混合候選時到 `8`；注音 `⇧1`…），因為那裡用數字選詞；行動裝置不顯示編號。
- 組字（iOS 文字欄裡的標記文字）分音節：拼音音節之間 U+2006（ni hao），注音 U+2004（ㄋㄧˇ ㄏㄠˇ）；不是拼音的字母（iphone）和全大寫照打的顯示。引擎內仍是原始按鍵。
- 文字寬度量測要快取（以文字＋字級為鍵），每次按鍵不重新量測未變的候選。

全寬 iPad 鍵盤（iOS）在最下排右端多一個隱藏鍵盤鍵（`keyboard.chevron.compact.down`，1.25 鍵寬），和 Apple 鍵盤一樣；浮動鍵盤沒有。

iOS 鍵盤自己不畫底：系統鍵盤的半透明底（iOS 26 起）透出在按鍵、貓和玻璃後面。按鍵照 iOS 27 Apple 拼音鍵盤的樣子，字母鍵和功能鍵同色、沒有陰影：淺色鍵面 `white 0.90`、按下 `white 0.45`，字黑色；深色鍵面 `white 0.18`、按下 `white 0.36`，字白色。換行鍵（確認、傳送等）維持色系的強調色。預覽氣泡與替代字列不透明（淺色白、深色 `#6C6C70`）。減少透明度或增加對比時改回不透明：淺色鍵面 `#FFFFFF`、功能鍵 `#CFCED8`、鍵盤底 `#E9E8EF`→`#D9D8E0`；深色鍵面 `#5E5D63`、功能鍵 `#3C3B40`、底 `#252428`→`#1A191C`。實驗室 app 沒有系統底，在鍵盤後面放一塊代替色（淺 `#E2E3E8`、深 `#373737`）。

高度：iOS 27 不理會擴充鍵盤的高度約束，給固定高度（iPhone 18 Pro 直向 216 pt、橫向 160 pt）。放不下上表尺寸時，直向改用橫向的候選列與鍵距，橫向的候選列不放貓，鍵高照剩下的空間平分，每一排都在系統的地球／麥克風列上方。

增加對比（iOS）：按鍵加 1 pt 外框；選中候選的膠囊、替代字列的選取和強調色的換行鍵改用色系的深色（`CandidatePalette.color(dark: false)`），白字對比 5:1 以上。

## 6. 觸控（以 Apple 鍵盤為最低標準）

- 一個觸控面處理整個按鍵區，**按鍵間隙沒有死區**：觸點歸屬到同排最近的鍵，排與排以間隙中線分界。
- 多指交疊（rollover）：新手指落下時，若前一個字元鍵仍按著，立即送出前一鍵；任何按鍵都不能因打太快而遺失。
- 字元鍵在**放開**時送出；手指滑到別的鍵，預覽跟著移動，放開時送出最後所在的鍵。
- 預覽氣泡：手機在按下的同一幀出現（鍵形＋上方較寬的圓角氣泡，字級 34）；邊緣鍵的氣泡往內收；iPad 不顯示氣泡，只加深鍵面。
- 刪除鍵：按下立即刪一個；0.42 s 後以每秒約 12 次重複；連續 2.5 s 後改為整詞刪除。
- 空白鍵：放開時輸入；長按 0.4 s 進入游標模式（鍵帽字樣淡出），水平移動每 9 pt 移動一個字元。組字中不進入游標模式，長按後放開仍是空白鍵當時的動作（選詞、一聲）。游標模式中其他手指不輸入。
- Return：組字中鍵帽寫「確認」。拼音送出打的字母（nihao、iPhone），和 Apple 拼音的「确认」一樣；注音送出選中的候選。macOS 不變。
- Shift：按下立即生效；0.3 s 內連按兩次為大寫鎖定；按住 Shift 滑到字母，放開時輸入大寫並回到小寫。
- 長按字元鍵 0.45 s 顯示替代字列（英文重音字母、中文標點變體）。第一格是按鍵本身，開在手指下方；不滑動就放開，送出原鍵。滑動選擇、放開送出；手指移到按鍵下方一個鍵高以外，放開不送出。
- 符號頁：空白、撇號和中文句讀（，。？！、；：）之後回到字母；`.`、`,`、`:` 和數字後面的符號留在符號頁（3.14、12:30）。按住符號鍵打字，放開後回到原來那一頁。
- 日語模式有自己的符號頁，照 Apple 的日語羅馬字鍵盤：第 1 頁是數字、`ー` 和日文標點（`：；（）¥@「」`、`。、？！・`），第 2 頁是全形符號（`【】｛｝＼｜～『』…`）。組字中按 `ー` 會加進讀音（ge、ー、mu 是ゲーム），然後回到字母頁；沒有組字時照常輸入。
- 數字、小數和數字與標點的欄位（`numberPad`、`decimalPad`、`asciiCapableNumberPad`、`numbersAndPunctuation`）打開時直接在數字頁。
- 聲音：`UIDevice.playInputClick()`（遵守系統鍵盤按鍵聲設定）。沒有觸覺回饋：iOS 只讓開啟「完整取用」的鍵盤震動，而喵撲不要求完整取用。
- 所有按鍵都是無障礙元素，帶 `keyboardKey` 特性與正確的繁簡標籤。

## 7. 動態

- 眨眼：每 2.8–6.4 s 隨機一次（120 ms），莫莫偶爾連眨兩下；組字時兩隻貓微微傾向候選。
- 摸米米莫：縮一下並搖頭，有時笑（iOS 鍵盤不能畫到自己的上緣之外，他的耳尖就在上緣，所以動作不高過靜止時的高度；桌面可以跳）；摸莫莫：蹭手、臉紅，連摸五下切換繁簡，兩下間隔超過 1.6 s 重新計數。
- 送出文字時米米莫動一下（同上）。所有動作都是事件觸發，閒置鍵盤不持續重繪。
- 降低動態效果：只保留眨眼與淡入淡出。
- Windows：只有眨眼、摸貓時的笑臉和連摸莫莫五下切換繁簡；沒有傾向、搖頭、蹭手和淡入淡出。

## 8. 效能預算

- 每次按鍵：引擎＋介面更新在 iPhone 上 < 8 ms。主執行緒不讀寫整個檔案；每次按鍵只對已開啟的唯讀 `language-evidence.sqlite` 做索引查詢（模擬器上含查詢的按鍵處理中位數 0.3–1.1 ms，實機冷啟動時的延遲還沒量）。
- iOS 鍵盤只有一個 `glassEffect`（候選玻璃，展開時再加一個面板）；按鍵不用玻璃材質，以 CALayer 繪製，陰影使用預先設定的 `shadowPath`。
- 貓是點陣圖；表情切換只改不透明度。
- 記憶體：目標是鍵盤擴充常駐 < 40 MB。Rust 核心直接讀取映射的 mimo_base.bin，詞庫在堆積上佔 0 位元組（之前拼音 33.0 MiB、注音 22.7 MiB）。映射的檔案頁是乾淨的檔案頁，不計入 phys_footprint：Mac 上只載入拼音詞庫並打一個詞的行程，phys_footprint 從 38.5 MiB 降到 1.8 MiB。模擬器 Release 之前量到拼音 62.7 MB、注音 50.4 MB、日語 25.7 MB，這是改動前的數字；扣掉詞庫約為 30 MB 與 28 MB，還沒重量。上架前要在模擬器與實機重量。
