# 輸入體驗檢查

2026-11-08。這份記錄保留各輪開發時的測量與限制；下文的「尚未安裝」指各輪檢查當時。修復現收錄於 0.4.3 Alpha 1，iOS 0.4.3（43）已安裝並啟動於開發用真機，尚未完成本版鍵盤實際輸入驗收。目標是讓喵撲可以安心作為日常主力輸入法；目前不能宣稱已達到蘋果輸入法的整體體驗。

## 怎樣判斷有沒有變好

| 面向 | 驗收方式 | 本輪狀態 |
| --- | --- | --- |
| 不丟字、不串欄位 | 分段選詞、連續刪除、切換欄位、切換輸入法、宿主拒收；核對每次提交及剩餘讀音 | 補上宿主選區、欄位隔離、提交重試回歸；仍需各平台真實應用驗證 |
| 候選可達、排序合理 | 拼音／注音、繁／簡、單字／詞／長句；逐鍵檢查而非只看打完後的結果 | 修完整音節證據及分段候選去重；沒有按個別詞增添例外 |
| 長句不中斷 | 只輸入下一音節的前半、選句首、繼續輸入，檢查後綴完整保留 | 共用核心回歸涵蓋中文及拼音中日混打 |
| 手感穩定 | 同機同詞庫測普通輸入和長句的逐鍵延遲，分開記冷啟動、核心計算和畫面延遲 | 本輪測主機核心和 Swift 後端；不能代替手機觸控到畫面的延遲 |
| 畫面可讀、可操作 | 小螢幕、橫屏、最大文字、VoiceOver、降低動態效果／透明度、鎖屏恢復 | 自動檢查版面尺寸和按鍵狀態；實機視覺與輔助功能尚未驗收 |
| 個人詞庫可靠 | 只學確認的候選，區分繁簡及輸入模式，編輯或換欄位後不學錯誤相鄰詞 | 修短期學習邊界；Android 和 Windows 仍未有完整同等功能 |

簡體拼音使用簡體詞源的權重。繁體的顯示轉換不能取代簡體的詞頻和語境。評估時會分開看四種模式，不能以一種模式的結果代表全部。

人工例句只用於發現問題；「指定答案在首屏」不等於輸入法準確率。已有開發集與已揭曉的驗證集見 [拼音評估](PINYIN_EVALUATION.md)。本輪沒有拿已揭曉驗證集調參，也沒有改詞條來迎合它。下一次評估排序品質需另準備未參與調整的材料。

## 第一輪修正

### 共用核心

未完成音節的判定原本只掃桶內前 64 個詞條；高頻縮寫或繁簡變體擠在前面時，真實單字讀音可能被忽略。現在載入詞庫時建立完整的單字讀音索引，完整拼寫檢查也共用此索引。這修的是資料查找範圍，不是把某幾個字的權重拉高。

部分長句候選先按顯示文字去重，再計算名額，避免幾個繁體變體合併後佔掉其他簡體候選的位置。同一次按鍵內重複需要的完整拼音解碼結果只計算一次，保留原有搜尋寬度與分數。

### macOS 與共用學習

沒有自己的組字範圍時不再送出空的 marked text。按 [Apple 的文字輸入契約](https://developer.apple.com/documentation/appkit/nstextinputclient/setmarkedtext(_:selectedrange:replacementrange:))，這種呼叫可能取代宿主目前選中的文字。修正保留取消組字及部分上屏後的後綴更新。

短期相鄰詞學習現在有明確的終點：切換欄位、移動游標、刪除已上屏文字、宿主快捷鍵及中英模式切換。正常的連續中文選詞仍可累積個人詞組，已儲存的記憶不會因切換欄位被清除。

### iOS

每次按鍵、點候選和送出文字前核對文件識別碼，不只等待 UIKit 的文字變更回呼。新欄位會捨棄舊組字的本地狀態與臨時學習上下文，過期候選點擊不會帶入新欄位；同一欄位最初尚未取得識別碼的情況則保留組字。這依據 [UITextDocumentProxy 的文件及變更通知](https://developer.apple.com/documentation/uikit/handling-text-interactions-in-custom-keyboards)處理；識別碼暫時不可用時仍有宿主相容性邊界，不能宣稱涵蓋所有應用。

返回鍵標籤及語言未改變時不重複更新。旋轉或掛載期間候選區短暫為零寬時，不再因同時保留日語候選而計算出負寬度。

### Android 與 Windows

Android 已從核心取出的文字，在目前編輯階段保留到宿主接受為止；拒收時顯示重試，不先把後綴寫到前綴之前。更換欄位或結束編輯時清除待送內容，避免跨欄位洩漏。這是暫時拒收的保護，不是應用關閉後的文字復原功能。

Windows 的 TSF 鍵盤處理加入左右 Windows 鍵檢查，把系統快捷鍵交回系統。

本輪 macOS smoke 共 646 項通過，涵蓋真實 `NSTextView` 選區／組字與拼音、注音、繁簡的學習邊界。普通拼音按鍵主機測量為 median 0.20 ms、P95 0.60 ms；這不是視窗繪製或冷啟動時間。

全部 22 個核心檢查通過。新的獨立查找測試與正式詞庫逐一核對 506 組音節／前綴及 1,646 組帶調證據。同機同詞庫交錯跑三輪 `check_pinyin_mixed_progression.py`，每輪 P95 的中位數如下：

| --- | ---: | ---: |
| 自然長句 | 7.597 ms | 6.334 ms |
| 重複音節壓力輸入 | 11.513 ms | 9.936 ms |

索引增加 29,488 bytes 常駐資料；七次交錯載入的中位時間從 37.338 ms 增至 45.884 ms。這是以約 8.5 ms 一次性載入成本換取逐鍵少做重複查找，仍須在手機核對冷啟動與記憶體。這些數據沒有包含 Apple 輸入法對照。

iOS 的 8 組邏輯測試、模擬器編譯通過。Android 的 API 35 Java 編譯及待送文字、混打選取、候選策略測試通過。Windows 的待送佇列、標點、繁簡及 SQLite 詞條測試與 x64 DLL 交叉編譯通過。iPhone 目前離線，Windows／Android 沒有本輪實機結果。

## 第二輪：游標語境、記憶與平台狀態

macOS／iOS 開始一段中文組字時，將游標前最多四個連續漢字送入現有的語境排序；拼音、注音、簡繁共用這條路徑。macOS 僅查詢前八個 UTF-16 單位，拒絕選區、無效位置、不完整回覆及系統保密輸入狀態。iOS 使用系統提供的 `documentContextBeforeInput` 片段，再取相同的漢字後綴。兩邊都不跨標點、空白、英文、emoji 或換行，不取游標後文，不保存宿主前文；查不到就維持原排序。

只有開始讀音的按鍵會查詢；組字中的按鍵、空閒刪除、空格不反覆向宿主要文字。部分選詞和刪改讀音沿用同段語境；下一次開始組字重新取得當前欄位的資料。這是既有詞庫語境分數的接入，不是語意模型，也不等於任何句子都能選對。

個人詞庫的「忘記」現在一併刪除該讀音的上下文記錄；「清除」立即持久化，避免關閉程式後舊快照復活。開關記憶、清除及忘記會使臨時學習上下文失效。載入時限制記錄數、清除無效值與重複，防止異常使用次數溢位；損壞檔案不再被普通 `flush()` 覆寫。一般學習仍延遲寫入，沒有改成每鍵寫磁碟。

第二輪整合結果：macOS 789 項 smoke 通過，包括上下文傳遞、刪改讀音、選詞消耗、空語境回退與記憶隔離；iOS 模擬器編譯和 8 組邏輯測試通過。尚未安裝到日常使用的輸入法或 iPhone。這些是程式與模型測試，不是宿主相容性、真機觸控延遲或 Apple 輸入法對照測試。

Windows 接入 TSF 欄位移除通知，釋放已關閉欄位的會話及引用；欄位關閉或服務停用後，晚到的非同步提交不再執行。正常切換焦點仍保留各欄位的組字，沒有強行提交或按容量淘汰。佇列測試含晚到回呼與跨欄位隔離，普通執行及 AddressSanitizer／UndefinedBehaviorSanitizer 通過，x64 DLL 交叉編譯通過；TSF 實際事件投遞仍待 Windows 驗證。

Android 移除固定 312 dp 最低高度與垂直置中，依目前視窗、安全區、列數與高度偏好排版。一般拼音內容自然高度為 268 dp；小視窗可收至 230 dp，注音為 274 dp，另加系統安全區。按鍵列與候選條維持至少 44 dp 縱向點擊範圍，展開候選不改變鍵盤總高。192 組幾何測試及 API 35 Java 編譯通過；極矮視窗低於幾何下限仍需更大的編輯空間，未完成實機驗收。

## 第三輪：連續輸入與候選穩定性

個人記憶原本會觸發整排候選按單字詞頻重新排序，抵消前文帶來的次序；即使記憶中的詞已不在候選裡，也會重排其他字。修正後只允許有實際記憶加分的候選向前移，保留其餘候選的相對次序與跨語言位置。新增拼音／注音、簡繁的回歸，檢查舊詞已失效、強化原首選、重複刷新及實際提交的文字；修改前可重現 15 個失敗斷言，修改後全部通過。沒有為例句改詞頻。

核心修正單字後備候選的切段邊界：不得在聲調或明示分隔符前截斷，避免選詞後留下孤立聲調。`Core/tests/check_composition_state.py` 使用生成詞庫及固定亂數種子，涵蓋拼音／注音、繁簡、普通／Android 完整候選模式，共 12,044 次操作、15,854 次狀態檢查；438 次選詞中有 291 次部分選詞。核對剩餘讀音、候選 metadata、上屏佇列、退格、取消、翻頁、切換字形及容量邊界。修改前同一測試會在候選留下孤立聲調時失敗。這是狀態正確性測試，不是自然語言排序準確率。

iOS 的長按刪除與空格游標手勢在欄位切換、鍵盤隱藏或場景失去活躍時取消；遲到的放手或移動回呼不再補打一個空格或刪到新欄位。手勢 driver 增加取消、重複放手、遲到開始、無效座標與取消後恢復的測試。

Android 將成功上屏引發的延遲／合併通知與外部游標操作分開處理。宿主取消組字、清空或貼上後，不再沿用舊讀音。待送文字期間若游標移動，暫停自動重試，使用者點提示後才送到目前位置；若宿主拒絕結束舊組字區，先保留文字，不直接覆寫。長按動作在鍵盤隱藏、結束輸入、重建及移除視圖時取消。模型只保留最近 32 次成功寫入的位置預期；異常宿主的更長延遲或非標準回呼仍需真機排查。

第三輪驗證：macOS 837 項 smoke 通過；普通拼音主機逐鍵計算 median 0.20 ms、P95 0.63 ms。iOS 模擬器編譯與 8 組邏輯測試通過。核心狀態測試及相鄰的長句、混打、容量、單字及 C ABI 回歸通過。Android API 35 Java 編譯、選區通知、暫停提交、192 組版面與既有候選測試通過。手機手勢尚未實機驗證，程式也尚未安裝或發布。

## 第四輪：完成文字的交付與失焦恢復

共享 Engine 原本在切換輸入方式時，連同尚未送出的完成文字一起清除。macOS 試打頁的「完成組字 → 切換模式」可穩定重現；拼音、注音與繁簡共八個失敗斷言。現在成功切換引擎後保留待送文字，連續切換仍只取出一次；試打頁點選候選或切換模式後也會送出，不必等待下一次按鍵。沒有改變取消組字或由宿主決定何時完成組字的規則。

iOS 暫時取不到已知文件的識別資訊時，保留已選前綴、未完成讀音與待送文字，暫停寫入和手勢。同一文件恢復後續接，確認換到另一文件才清除舊的本地狀態。設定中的模式切換也延後到文件可確認時。這是本地狀態機修復；系統沒有提供 marked range 查詢或寫入回執，鎖屏後宿主是否保留原組字區仍要真機跨 App 驗證。

Windows 現在暫停失焦欄位的交付佇列，晚到的 TSF 編輯回呼不會立即寫入；返回原欄位並收到可處理的按鍵後重試。選詞清空讀音但文字尚未上屏時，後續數字、空格會跟在佇列後方，避免先於中文出現。Enter、刪除、游標等直接交宿主的命令，仍未全面納入同一順序機制。

核心狀態測試新增聲調、無調和明示分隔符交錯的情況，11,323 次操作、15,114 次檢查及 288 次部分選詞通過。另修正混日總分的 `int` 溢位：合法的極端自訂權重原本會觸發 UBSan，改用 64 位累加後通過，正常排序公式未變。它不是常用詞排序品質的提升。

macOS 完整建置和 855 項 smoke 通過，普通拼音主機逐鍵計算 median 0.21 ms、P95 0.62 ms。iOS 模擬器編譯與 8 組邏輯測試通過。Windows 佇列、標點與實際核心部分選詞測試、x64 DLL 交叉編譯通過。這輪沒有重裝使用中的輸入法或發布安裝包；iOS 鎖屏恢復及 Windows 宿主互動尚無本輪真機驗證。

## 第五輪：長句前段與個人排序

這輪沒有補例句詞條、調整個別詞頻或擴大搜尋 beam。修正核心的兩個通用條件：較短整詞已出現時，仍可在它之後搜尋更長的完整前段；上下文加分只比較讀音消耗範圍相同的候選，避免把短前段推到既有完整長句之前。合成詞庫的長前段首屏檢查由 0/24 改為 24/24，拼音／注音、繁簡的完整長句順位檢查由 0/4 改為 4/4。這些是根因回歸，不是自然語言命中率。

拼音下一個詞還未打完時，也沿用既有分段器列出已完成前段中的較早切點。分段最多三個，先保留不同切點，再以空位保留同切點的次選，不增加 beam 或為次選另做解碼。合成詞庫早期分段檢查 0/24 → 24/24；已知的 `wobayaos`、`wobayaosh`、`qingbachuangh`、`bagangcaidewenj` 在繁簡下共八項首屏檢查通過。84 次選詞／續打確認尾音和提交文字正確。

macOS／iOS 的共享記憶層不再排除超過八字的完整中文句子。測試實際選取非首位長句兩次，再次輸入時可前移；保留核心原有來源、索引和消耗資訊，不把同文短前段當成完整句子。拼音／注音、繁簡共 36 項新檢查，修前四項排序失敗，修後通過；忘記記錄後恢復原排序。既有儲存上限及至少兩次選取的門檻不變。

新增 `Core/tests/check_long_sentence_holdout.py` 逐鍵診斷 12 組日常組合句，對照無聲調簡體拼音和帶聲調注音。這是本輪整理的回歸材料，並非獨立受試者語料；工具區分詞庫可分解性、目標順位、前段消失與選取契約。只有提交或剩餘讀音違反契約才視為硬失敗，語義缺口會完整保留在報告中。

同一批逐鍵診斷中，拼音曾失去指定正確前段的句子由 10/12 降至 6/12，注音仍為 3/12。這個指標觀察整個候選池，不要求所有早期切點永遠保留，因此用來定位缺口，不單獨作為品質分數。完整目標前五命中維持拼音 8/12、注音 12/12；拼音仍有三句指定完整文字未出現，雖然都能由詞庫分解。兩種模式各 36 次部分選詞與續打通過。舊版 36 題 validation 的分組名次統計未變，未將這些已看過的題目聲稱為新驗證集。

固定長句基準單次同機 P95：自然長句 6.881 → 6.890 ms、重複音節 10.968 → 11.038 ms，約持平；不是提速結論或手機端到端延遲。核心相鄰回歸與 11,323 次狀態操作通過。

最終 macOS 完整建置及 891 項 smoke、iOS 模擬器編譯和 8 組邏輯測試通過。本輪未替換使用中的系統版、未安裝 iPhone 或發布。診斷快照保存在 `.build/long-sentence-progression-round5-before.json` 和 `.build/long-sentence-progression-round5-after.json`；它們包含核心與詞庫校驗值，供下一輪比較。

## 第六輪：同音前段的保留與搜尋成本

拼音與注音原本在某些切點只留下第一種解讀。下一個音節出現後，原本可選的正確同音前段會從整個候選池消失。現在重用同一次解碼的其他結果：拼音最多補六個同音前段，注音在最近有效切點最多補兩個。原有切點優先，拼音額外選項接在原候選後方，避免推遲已存在的完整句。未加歷史候選快取，改聲調、退格重打及新組字仍由目前讀音重新計算。

`check_prefix_continuity.py` 涵蓋 12 條拼音／注音、繁簡逐鍵路徑和合成詞庫；修前 14 處候選消失，修後全可選，其中六條實際路徑的最終目標位於前七。選取後保留精確尾音，改聲調不保留舊候選。另用五條完整句、同一切點多個同音詞的合成資料，確認額外分段不擠走完整句的原有位置。macOS／iOS 共用 Engine 的六條注音回歸也檢查了前段上屏及尾音續打。

新增並凍結 20 組日常句子（`Core/tests/data/long-sentence-round6.tsv`），與上一輪 12 句不同，全文未出現在三份本地人工覆蓋表。它仍是開發時整理的材料，不是受試者語料或使用準確率。基線源碼、工具、詞庫及題目校驗值保存在 `.build/long-sentence-round6-freeze/`。最終結果：

| 同一批 20 組診斷 | 拼音修前 → 修後 | 注音修前 → 修後 |
| --- | ---: | ---: |
| 曾失去指定正確前段的句子 | 14 → 9 | 5 → 1 |
| 按指定目標貪婪分段可完成 | 12 → 14 | 19 → 19 |
| 完整目標位於前五 | 9 → 9 | 18 → 18 |
| 完整目標可找到 | 11 → 11 | 19 → 19 |
| 部分選取及續打契約通過 | 60 → 60 | 60 → 60 |

最終 40 組完整目標的名次與基線相同。分段成本由工具在知道目標的前提下，於完整輸入後反覆選最長正確前段；這不是最優策略，也不等於真人按鍵成本。報告為 `.build/long-sentence-round6-baseline.json` 與 `.build/long-sentence-round6-final.json`。

整句搜尋的缺口尚未解決。診斷發現同音詞先按靜態頻率截前五，再計上下文分，有搭配證據的後續詞可能過早出局。`check_sentence_search.py` 預設會明示已知缺口；加 `--require-context-search` 可將它作為失敗檢查，不能把預設成功退出說成缺口已修復。

本輪評估但未合入的方案包括後綴多樣性、上界搜尋及查詢內快取；它們有品質或耗時退步。明示把詞候選預算改為六、輸出路徑仍為五的方案，雖通過合成根因測試，舊題集和新 20 題均未見實際收益，壓力輸入 P95 卻增加約 17%，因此也未合入。詞庫、詞頻及原有搜尋預算未變。

最終分段修正同機交錯三輪測量，P95 中位數：自然長句 6.881 → 6.938 ms，重複音節 10.990 → 11.005 ms。這是本機核心耗時，沒有包含手機、宿主編輯或視窗繪製。

最終 macOS 建置及 915 項 smoke、iOS 模擬器編譯及 8 組邏輯測試通過；核心 11,323 次狀態操作、前段／聲調／上下文回歸通過。舊 validation 的逐題順位未變。本輪沒有替換日常使用的系統輸入法，也沒有真機安裝或發布。

## 仍需完成的體驗差距

| 優先順序 | 差距 | 下一步驗收 |
| --- | --- | --- |
| 1 | macOS／iOS 已接入短左語境，但沒有右語境或完整語意模型 | 真實應用測移動游標、貼上、刪改及換欄位；獨立評估排序是否減少修改 |
| 1 | 尚無完整的讀音中段編輯與已上屏文字重新選詞 | 保持候選與原始讀音位置對應；測中文、emoji 及混合字串，不以重新輸入整句代替 |
| 1 | Windows 實際 TSF 功能落後於可攜式 Session，缺完整宿主組字，現有 TSF 路徑只有拼音 | 整合 Session 與組字生命週期後，測注音、切欄位、非同步編輯與終止組字 |
| 2 | Android 缺持久個人學習；英文辨識仍依有限詞表，自適應版面尚未實機驗證 | 使用與其他平台一致的學習語義；用未參與開發的中英混合材料及不同尺寸驗證 |
| 2 | 長句排序尚無代表真實使用分布的獨立評測 | 固定新測試集，以完成一句所需選詞／改字次數對照 Apple，並記錄逐鍵候選變化 |
| 2 | 缺同機 Apple 輸入法的端到端操作對照、實機記憶體及掉幀結果 | 在隔離文字框測試，不打斷日常輸入；測冷啟動、長時間打字、橫屏與輔助功能 |
