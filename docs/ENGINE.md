# 引擎與詞庫

## 執行時

Core/MeowpuutCore.cpp 提供 C++17 中文解碼器與 C API。不可變詞表供會話共用，每個會話獨立保存組字、候選、頁碼與提交內容。拼音和注音各有讀音索引，共用詞條字形與頻率來源。

Swift 的 ChineseWithJapaneseBackend 合併候選。英文判斷使用本機規則；日語使用 Romaji 轉假名與小型單字表。收合時保留一個日語候選，展開後按引擎排序顯示；完整中文候選和已學會的用詞仍會參與排序。這不是通用語言辨識或完整日語句法解碼。

## mimo 1.0 統一詞庫

編譯器 scripts/compile-native-lexicon.py 的合併順序：
1. 校驗兩份上游快照的 SHA-256。
2. 讀取 McBopomofo 的字形、讀音和詞頻，配對簡體字形。
3. 將 Pinyin Pro 帶調拼音正規化，按簡體詞面、帶調讀音與繁體詞面合併；相同簡體與讀音的不同繁體字詞各自保留，不同讀音不合併。
4. 保留原有 `weight`，包括用共同詞條的對數頻率差中位數校準繁體獨有詞尺度、再減 350 的既有規則。另按「簡體字形＋完整帶調讀音」查 Pinyin Pro 分數，作為 `hans_weight`；沒有直接匹配時回退 `weight`。兩個分數是排序先驗，並非兩份語料真實使用量的統計比較。
5. 套用本地修訂。明確修訂的詞條在兩種字形均沿用人工權重，即使低於上游；衍生單字仍照來源配對及讀音核對。`Resources/Lexicon/simplified-priorities.tsv` 另記只影響簡體排序的編輯權重：每項須有同簡體詞面及帶調讀音的 Pinyin Pro 來源，且不得與雙字形人工詞條衝突；這些權重是產品排序決定，不是實測詞頻。生成的 manifest 記錄檔案校驗值。按逐字對齊和 `ni3` 讀音處理「妳」的簡體顯示，生成的 `simplified-pronoun-audit.json` 記錄處理項目。
6. 輸出完整 SQLite 詞庫與拼音、注音讀音索引。V2 索引表頭為 `MEOWPUUT-PINYIN-2` 或 `MEOWPUUT-ZHUYIN-2`，資料行依序為 `bare`、帶調讀音、繁體、簡體、`weight`、`hans_weight`；行的排序和原五欄與舊版一致。SQLite 的 `lexicon` 也保留 `weight` 並另設 `hans_weight`，供簡體查詢排序。

V2 的 `# context` 區以繁體詞面為鍵，每行依序存放繁體和簡體上下文權重，分別從同一詞面的完整讀音取對應模式最高分；`context.tsv` 的人工優先級同時適用兩種模式。新版解碼器也接受舊版只有一個上下文權重的資料，將該權重用於兩種模式；舊版解碼器不能讀取新的三欄上下文，程式與資料須一起更新。這些上下文分數是排序依據，並不保證完整句子的語意正確。

字形轉換使用隨專案提供的固定 ICU 78.2 轉換快照與人工覆寫；四個平台離線建置使用同一份資料。缺少新詞的轉換時會停止建置，經審核後更新快照。沒有明確對應的新詞可能遇到一簡對多繁的歧義，應以本地修訂校正。合併不會刪掉繁體專有表達或多音字；同義但不同寫法也不冒充重複詞。

lexicon-merge-report.json 記錄去重、來源新增、排除數量、頻率校準與索引規模。V2 詞庫須與支援 V2 的程式一起發布；舊版程式不能讀 V2。單字查找、前綴補全和誤拼修正使用有界搜尋；不會在每次按鍵時掃描整份詞庫。

`scripts/audit-mimo-corpus.py` 的第二版審核報告分別列出 `traditional_weight` 和 `hans_weight`，簡體變體按後者排列；審核舊 SQLite 時以 `weight` 作簡體回退並明確標示。分數本身不能證明詞條由哪個來源提供，來源證據仍須另行核對。

## 更新與個人詞庫

python3 scripts/update-simplified-lexicon.py 只檢查上游；加 --apply 才更新快照。更新後重新建置、執行 --smoke 與資料檢查，不在使用者輸入時下載資料。

ChoiceMemory 只學習已確認選詞，以及短時間相鄰選詞形成的短語。資料保存在本機，與捆綁詞庫分開，可停用或清除。沒有聊天記錄讀取或雲端同步。

完整選過至少兩次的中文長句也能成為個人候選，不再只回用八字以內的詞。記錄仍限制為每條最多 100 字、讀音最多 256 字元、每個讀音八個選項及總共 5,000 個讀音。若同句已由核心解碼，沿用它原本的候選索引和讀音消耗資訊；同文但只轉換前段的候選仍分開保留。這條個人記憶路徑目前由 macOS／iOS 的共享 Swift 適配層使用。

## 測試邊界

--smoke 涵蓋繁簡、拼音／注音模式隔離、誤拼、單字母、長句、候選翻頁、日語保留、個人記憶與候選尺寸。它不是輸入準確率評測；毫秒測量也只是測試批次內的引擎耗時，不等於端到端輸入延遲。

Windows 的 TSF 輸入服務仍需在真機和不同應用中驗證。iOS 尚需真機記憶體、跨 App、安全輸入欄位與無障礙驗證。
